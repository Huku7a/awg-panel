# AWG Panel

Веб-панель для управления **AmneziaWG** на серверах с нативной установкой AmneziaWG:
просмотр статуса, добавление, отключение и удаление клиентов, QR-коды и скачивание
конфигураций. Поддерживает управление несколькими серверами через лёгкий агент на
каждом узле и умеет **устанавливать и обновлять сами пакеты AmneziaWG** — без ручного
SSH и без разрыва активных сессий.

Работает поверх уже установленного AmneziaWG: не требует Docker и миграции, использует
тот же файл конфигурации `/etc/amnezia/amneziawg/awg0.conf` и применяет изменения через
`awg syncconf` — существующие соединения при этом не сбрасываются.

## Особенности

- **Клиенты**: список с состоянием (онлайн / оффлайн / выключен), IPv4, endpoint, трафик Rx/Tx
- **Поиск и сортировка** клиентов прямо в таблице (по имени, IP, статусу, подключению, трафику)
- **Создание клиента**: автоматический выбор свободного IP, своя ключевая пара + PSK
- **Включение / отключение** клиента без потери конфигурации (ключи сохраняются)
- **Удаление клиента** и генерация `.conf` + QR-кода для приложения AmneziaWG
- **Несколько серверов**: центральная панель + агент на каждом VDS (аутентификация по `X-Api-Key`)
- **Статистика подключений и трафика** по каждому клиенту за 24 часа / 7 / 30 дней или произвольный
  срок: график Rx/Tx, время онлайн, число подключений, колонка «Всего с начала», экспорт CSV.
  Отдельная вкладка «Статистика», кнопка «Стат.» в строке клиента и сводка по всем серверам
- **История не теряется при перезагрузке VDS**: трафик и факт перезагрузки пишутся в SQLite
  на самом узле, поэтому восстанавливаются из накопленных данных, а не из счётчиков ядра
- **Авто-деплой агента** на новый VDS прямо из панели по SSH-кредам — с пошаговым прогрессом в UI
- **Установка и обновление AmneziaWG** из панели: фоновая задача с логом шагов, индикацией
  прогресса и результата; агент сам в фоне проверяет доступные обновления каждые 6 часов
- **Безопасность**: Basic-авторизация панели, Bearer-токен агента, авто-бэкап конфига перед изменениями

## Архитектура

```
        Браузер
           │   Basic Auth (HTTPS — за reverse proxy)
   ┌───────▼────────┐        X-Api-Key (Bearer)        ┌───────────────┐
   │   AWG Panel    │ ───────────────────────────────► │  AWG Agent    │
   │   (FastAPI)    │        http://VDS:5183            │  (FastAPI)    │
   │     :5182      │        UFW: только для IP панели  │     :5183     │
   └───────┬────────┘                                   └───────┬───────┘
           │  /etc/amnezia/amneziawg/awg0.conf                   │  команды awg
           └────────────  (черeз `awg syncconf`) ────────────────┘
```

- **Panel** — единая точка входа: веб-интерфейс, хранение списка серверов и клиентов.
- **Agent** — лёгкое приложение на каждом узле: выполняет операции с AmneziaWG на месте.
  Панель общается с ним по HTTP, секреты передаются заголовком `X-Api-Key`.
- Порт UFW на узле открывается **только под IP панели** остальных узлов (см. «Безопасность»).

## Требования

- Сервер Ubuntu/Debian с правами **root**, где уже установлен и настроен AmneziaWG:
  - `awg` и `awg-quick` в `PATH`;
  - конфигурация `/etc/amnezia/amneziawg/<iface>.conf` и каталог `/etc/amnezia/amneziawg/params` (по умолчанию интерфейс `awg0`);
- Python 3.9+ (устанавливается автоматически);
- Порт панели должен быть доступен извне (скрипт сам открывает его в UFW, если UFW активен).

## Установка панели (одной командой)

Выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Huku7a/awg-panel/main/deploy/install-panel.sh | bash
```

Скрипт: проверяет AmneziaWG, клонирует код, создаёт виртуальное окружение, генерирует
случайный пароль, запускает сервис `awg-panel` (systemd) и выводит **URL, логин и пароль**.

Либо из клона репозитория:

```bash
git clone https://github.com/Huku7a/awg-panel.git && cd awg-panel
bash deploy/install-panel.sh
```

| Опция                 | По умолчанию  | Описание                                     |
|-----------------------|---------------|----------------------------------------------|
| `--user NAME`         | `admin`       | логин панели                                 |
| `--password PASS`     | случайный     | пароль панели (при повторе сохраняется прежний) |
| `--port N`            | `5182`        | порт панели                                  |
| `--interface IF`      | `awg0`        | имя интерфейса AWG                           |
| `--dir PATH`          | `/root/awg-panel` | каталог приложения                        |
| `--repo URL`          | ваш репозиторий | URL репозитория при клонировании           |
| `--no-ufw`            | —             | не открывать порт в UFW                      |

## Подключение второго сервера (VDS)

### Автоматически, из панели (рекомендуется)

В панели: **Сервер → Управлять серверами → «Развернуть агент»**. Укажите имя, хост и
SSH-креды — панель сама:

1. подключится по SSH (SFTP) и скопирует код агента;
2. установит агент: venv, systemd-сервис `awg-agent` (порт `5183`), случайный Bearer-токен;
3. откроет в UFW узла порт `5183` **только для IP панели**;
4. проверит подключение и автоматически добавит сервер в панель.

Ход установки отображается пошагово в UI; SSH-пароль используется одноразово и не сохраняется.

### Вручную

С центрального сервера:

```bash
bash deploy/deploy-agent.sh root@1.2.3.4 <IP_панели> [токен]
```

или на самом VDS:

```bash
# скопируйте каталог проекта на узел (например, /root/awg-agent) и выполните:
bash /root/awg-agent/deploy/install-agent.sh <IP_панели> [токен]
```

`install-agent.sh` создаёт venv, записывает токен в `/etc/awg-panel/agent-config` (права `600`),
запускает сервис `awg-agent` на порту `5183` и открывает его в UFW только для IP панели.
Если IP панели не указан — порт открывается для всех (не рекомендуется; ограничьте доступ
самостоятельно).

После этого добавьте сервер в панели: **Сервер → Управлять серверами → URL + токен**
(кнопка «Тест подключения»). Разными серверами переключайтесь через селектор «Сервер».

## Установка и обновление AmneziaWG

Вкладка **AmneziaWG** в окне «Управлять серверами» показывает: версию пакетов `amneziawg` /
`amneziawg-dkms`, установленную на узле, доступна ли более новая версия, и когда проверялось
(агент проверяет в фоне каждые 6 часов или по кнопке «Проверить обновления»).

- **«Обновить AmneziaWG»** — обновляет пакеты только из официального репозитория AmneziaWG
  (`apt-get install --only-upgrade`); лишние пакеты не трогаются, конфигурация
  автоматически бэкапится;
- **«Установить AmneziaWG»** — для узлов, где пакеты не установлены;
- операция выполняется в фоне: в UI показывается индикатор прогресса и последовательность
  шагов (бэкап конфигурации → обновление индексов → установка → проверка версии), результат
  и ошибки. Активные соединения не разрываются.

> Если узлу не откуда скачивать пакеты, добавьте официальный репозиторий:
> `apt-get install amneziawg amneziawg-tools` по
> [инструкции AmneziaWG](https://docs.amnezia.org/en/documentation/amnezia-wg/).

## API

### Панель (`:5182`, Basic Auth)

| Метод   | Путь                          | Описание                                   |
|---------|-------------------------------|--------------------------------------------|
| `GET`   | `/`                           | веб-интерфейс                              |
| `GET`   | `/api/awg/status?server=`      | статус узла + состояние авто-проверки обновлений |
| `POST`  | `/api/awg/update?server=&action=` | запуск установки/обновления (возвращает `id`) |
| `GET`   | `/api/awg/update/{id}`         | статус фоновой задачи (`running` / `done` / `error`, шаги) |
| `GET`   | `/api/servers`                 | список серверов                            |
| `POST`  | `/api/servers`                 | добавить сервер                            |
| `POST`  | `/api/servers/{id}/ping`       | проверка доступности сервера               |
| `DELETE`| `/api/servers/{id}`            | удалить сервер из панели                   |
| `POST`  | `/api/deploy`                  | авто-деплой агента на VDS (SSH/SFTP)       |
| `GET`   | `/api/deploy/{id}`             | статус деплоя (пошаговый прогресс)         |
| `GET`   | `/api/stats?server=&days=&from=&to=&granularity=&client=&refresh=` | статистика клиентов (см. ниже) |

### Узел / агент (`:5183`, заголовок `X-Api-Key`)

| Метод   | Путь                                   | Описание                          |
|---------|----------------------------------------|-----------------------------------|
| `GET`   | `/api/health`                          | проверка готовности               |
| `GET`   | `/api/awg/status`                      | статус AmneziaWG + кэш проверки обновлений |
| `POST`  | `/api/awg/update?action=upgrade&#124;install` | фоновое обновление/установка (202 + `id`) |
| `GET`   | `/api/awg/update/{id}`                 | статус задачи                     |
| `GET`   | `/api/clients`                         | список клиентов со статусом       |
| `POST`  | `/api/clients`                         | создать клиента                   |
| `PATCH` | `/api/clients/{name}`                  | включить / отключить              |
| `DELETE`| `/api/clients/{name}`                  | удалить клиента                   |
| `GET`   | `/api/clients/{name}/config`           | скачать `.conf`                   |
| `GET`   | `/api/clients/{name}/qr`               | QR-код                            |
| `GET`   | `/api/stats`                           | статистика клиентов (тот же формат, что у панели) |

### Параметры `/api/stats`

| Параметр      | Значение                                                                     |
|---------------|------------------------------------------------------------------------------|
| `server`      | панель: `local`, id узла или `all` (свод по всем узлам)                      |
| `days`        | глубина отчёта в днях (`1`, `7`, `30`)                                        |
| `from`, `to`  | произвольный срок в UNIX-секундах (взаимоисключающе с `days`)                 |
| `granularity` | `auto` (по умолчанию), `hour` или `day`                                       |
| `client`      | имя клиента — в отчёте остаётся только он                                     |
| `refresh`     | `1` — снять показания `awg` перед отчётом (панель зовёт это сама)             |

Отчёт содержит `totals` (сумма за период), `clients` (по клиенту: `rx`, `tx`,
`online_sec`, `sessions`, `total_rx`/`total_tx` — «Всего с начала», `resets`),
`series` (бакеты для графика), `events` (`reboots`, `last_reboot`), `coverage`
(границы фактически собранных данных), `interval`, `retention_days`, `truncated`.
При `server=all` добавляются `merged`, `servers` и `errors[]` — недоступные узлы
перечисляются в `errors`, остальные отчёты всё равно возвращаются.

## Безопасность

- Панель — Basic Auth (логин/пароль из `/etc/awg-panel/config`, права `600`);
- Узел — только по Bearer-токену `X-Api-Key` (`/etc/awg-panel/agent-config`, права `600`),
  сравнение через константного-времени `hmac.compare_digest`;
- **Fail-closed**: без пароля панели / токена агента приложения отказывают в обслуживании
  (код 503). Оператор может явно это отключить переменной `AWG_ALLOW_NO_AUTH=1`;
- Перед любыми изменениями конфигурация AmneziaWG бэкапится
  (`awg0.conf.bak-<время>` в `/etc/amnezia/amneziawg/`);
- **SSH-деплой** агента пинует host key узла (trust-on-first-use,
  `/etc/awg-panel/known-hosts.json`) и отказывается подключаться при смене ключа;
- **Токен агента при деплое** передаётся по SFTP/`stdin`, а не аргументом командной строки
  (не светится в `ps`);
- **SSRF-защита**: URL агента не может указывать на loopback, private/link-local/reserved
  сети (включая cloud metadata `169.254.169.254`); для изолированных LAN — `AWG_ALLOW_PRIVATE_AGENTS=1`;
- **CSRF-защита**: мутирующие запросы принимаются только от своего `Host` либо из
  `AWG_ALLOWED_ORIGINS` (запросы без заголовка `Origin` — CLI/curl — не ограничиваются);
- Секреты не попадают в репозиторий: `state.json` и `servers.json` в `.gitignore`;
- Фоновые задачи обновления и деплоя очищаются из памяти (TTL 1 ч) — без неограниченного роста;
- Для публичного доступа ставьте панель за reverse proxy (Nginx / Caddy) с TLS —
  Basic Auth поверх HTTPS и rate-limit на уровне прокси это то, что нужно.

## Разработка

```bash
# локальный запуск панели на :5182
source venv/bin/activate
uvicorn app:app --host 0.0.0.0 --port 5182

# локальный запуск агента на :5183 (без прав root — тестовый режим)
AWG_AGENT_TOKEN=testtoken venv/bin/uvicorn agent:app --port 5183 \
  --env AWG_CONFIG_DIR=/tmp/awg-test
```

Переменные окружения панели: `AWG_PANEL_USER`, `AWG_PANEL_PASSWORD`, `AWG_PANEL_IP`,
`AWG_ALLOWED_ORIGINS`, `AWG_ALLOW_NO_AUTH`, `AWG_ALLOW_PRIVATE_AGENTS`,
`AWG_KNOWN_HOSTS_FILE` (панель/скрипты), `AWG_CONFIG_DIR`, `AWG_INTERFACE`,
`AWG_STATE_FILE`, `AWG_SERVERS_FILE`, `AWG_CLIENT_DIR`, `AWG_STATS_FILE`.

Переменные окружения агента: `AWG_AGENT_TOKEN`, `AWG_ALLOW_NO_AUTH`,
`AWG_CONFIG_DIR`, `AWG_STATE_FILE`, `AWG_SERVERS_FILE`, `AWG_CLIENT_DIR`.

Переменные окружения статистики (панель и агент): `AWG_STATS_FILE` (путь к БД, по
умолчанию `stats.db` рядом с `state.json`), `AWG_STATS_INTERVAL` (интервал опроса
счётчиков в секундах, по умолчанию `60`, минимум `10`),
`AWG_STATS_RETENTION_DAYS` (глубина хранения в днях, по умолчанию `30`,
допустимый диапазон `1`–`30`).

## Статистика

Собственный агент на каждом узле раз в `AWG_STATS_INTERVAL` секунд снимает счётчики
`awg show <iface> dump` и раскладывает **дельты** в SQLite (`buckets`, почасовые
бакеты), а в `peers` держит монотонные `total_rx`/`total_tx` и число сбросов
счётчика. Отсюда важные свойства:

- **Перезагрузка VDS не стирает историю.** Счётчики ядра при перезагрузке обнуляются,
  но уже накопленные бакеты остаются в базе; событие загрузки (`events`) фиксируется
  по `boot_id`, поэтому в UI видно, что перезагрузка была. Неизбежно теряется только
  хвост между последней выборкой и перезагрузкой (не больше одного интервала).
- **Пересоздание пира** (удаление и повторное добавление клиента с тем же ключом)
  распознаётся по уменьшению счётчика и считается сбросом, а не откатом.
- **«Всего с начала»** — сумма всех дельт с момента появления узла в панели, она не
  уменьшается при сбросах; это не сумма счётчика `awg`.
- **Онлайн** считается по интервалам опроса (±`AWG_STATS_INTERVAL`), **подключение**
  засчитывается при переходе оффлайн → онлайн; само по себе первое появление клиента
  подключением не считается.
- Глубина хранения ограничена 30 днями: старые бакеты и события удаляются при каждой
  выборке, а запрос длиннее 30 дней обрезается (в ответе `truncated: true`).

## Устранение неполадок

- **«509: Agent unreachable» при обращении к узлу** — проверьте, что агент запущен
  (`systemctl status awg-agent`), и что порт `5183` на узле открыт для IP панели
  (`ufw status`). Панель автоматически повторяет запросы при временных сетевых сбоях.
- **Пакет не обновляется** — убедитесь, что репозиторий AmneziaWG подключён и
  `apt-get update` на узле выполняется (см. раздел «Установка и обновление AmneziaWG»).
- **Пароль панели забыт** — он хранится в `/etc/awg-panel/config`; при повторном запуске
  install-скрипта старый пароль сохраняется.
- **В статистике пусто / «Данные доступны только с …»** — сбор идёт на самом узле и
  начинается с момента установки агента; у старых агентов (без `/api/stats`) вкладка
  покажет ошибку — обновите агента на узле. Пустая сводка по всем узлам при наличии
  локального AWG — это штатно: локальный узел всегда доступен как источник.
- **Не сходится трафик с `awg show`** — счётчики AWG обнуляются при перезагрузке и
  пересоздании пира, а статистика считает дельты; сверяйтесь с колонкой
  «Всего с начала» и отметкой о перезагрузках.
- **Растёт `stats.db`** — это нормально (почасовые бакеты), база чистится сама до
  30 дней; файл лежит рядом с `state.json` и не попадает в релизы и деплой агента.
